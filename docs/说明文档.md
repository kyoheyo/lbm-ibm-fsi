## 一、项目概述

本项目实现了一个高性能的**格子 Boltzmann 法（LBM）+ 浸入边界法（IBM）+ 流固耦合（FSI）**仿真框架，采用多语言混合架构，在性能、安全性和可扩展性之间取得平衡。

## 四、实现思路

### 4.1 设计原则

本框架遵循以下核心设计原则：

1. **各层只做最擅长的事**：计算密集型内核用 C++ 实现；安全驱动层用 Rust；科学计算与可视化用 Python。
2. **零拷贝或最小拷贝数据传输**：
   - Rust ↔ C++ 之间通过裸指针（C ABI）直接操作同一块堆内存；
   - Rust → Python 之间通过 pyo3 以 Python `list` 传递数组，避免写入中间文件。
3. **输出频率与开销匹配**：
   - 高频（每步或每数百步）：Rust 原生写出 NPZ 快照或 CSV 行，开销极低；
   - 低频（每数千步）：调用 Python 生成高质量云图，开销较高但频率低。
4. **Python 独立可用**：所有 Python 模块可在不启动 Rust 程序的情况下独立运行，适合离线后处理和脚本化工作流。

### 4.2 两种 Python 调用模式

| 模式 | 触发方式 | 数据传递 | 适用场景 |
|------|----------|----------|----------|
| **子进程模式** | `pre_script` / `post_script` TOML 配置 | 通过文件（TOML、NPZ/DAT/PLT） | 重量级预处理、完整后处理流水线 |
| **FFI 模式** | `python-ffi` Cargo 特性 + `plot_interval` | 直接内存传递（无文件） | 低频云图、实时诊断 |

两种模式互不排斥，可以同时启用。

### 4.3 如何选择输出格式

| 格式 | TOML 值 | 文件扩展名 | 文件大小 | 读取方式 | 适用场景 |
|------|---------|------------|----------|----------|----------|
| NumPy NPZ（**默认**）| `"npz"` | `.npz` | 较小（Deflate 压缩）| `NpzReader`（Python）| Python 后处理首选 |
| ASCII Tecplot | `"tecplot_asc"` | `.dat` | 最大（文本） | `TecplotAscReader` / Tecplot / ParaView | 需要人工检查或 Tecplot 绘图 |
| 二进制 Tecplot TDV112 | `"tecplot_bin"` | `.plt` | 最小（二进制）| `TecplotBinReader` / Tecplot 软件 | Tecplot 用户、存储受限场景 |

### 4.4 如何开启 FFI 实时云图

1. 在 TOML 中配置：
   ```toml
   [output]
   plot_interval = 2000   # 每 2000 步绘制一次（与 format 无关）

   [python]
   pythonpath = "python"  # 使 lbm_post 可直接导入
   ```
2. 以 `python-ffi` 特性编译（需要系统安装了 CPython）：
   ```bash
   cargo build --release --features python-ffi
   ```
3. 正常运行求解器，每隔 `plot_interval` 步会在进程内生成速度幅值和涡量云图，保存到 `output.directory`。未以 `--features python-ffi` 编译时，`plot_interval` 被忽略，不会报错。

## 五、模块间调用关系

### 5.1 完整仿真流程

```
┌─────────────────────────────────────────────────────────────────────┐
│                         完整仿真流程                                 │
│                                                                     │
│  ① 可选：Python 子进程预处理                                         │
│     lbm_pre.config_gen  → 生成 configs/*.toml                       │
│     lbm_pre.mesh        → 生成 domain.msh                           │
│     通过命令行参数传递配置文件路径                                    │
│                          ↓                                          │
│  ② Rust 主控（orchestrator/src/main.rs）                             │
│     读取 configs/*.toml                                              │
│     [可选] Python FFI：调用 lbm_pre.bridge.geometry_markers_raw()    │
│       → 直接获取标记点坐标（无 CSV 文件）                             │
│     调用 C++ 核心（FFI）运行 LBM 仿真循环                             │
│       每隔 write_interval 步 → NPZ 快照（Rust 原生写出）              │
│       每步（可选）           → CSV 一行（Rust 原生追加）               │
│       每隔 plot_interval 步  → Python FFI 云图（无 NPZ 中间文件）     │
│                          ↓                                          │
│  ③ 可选：Python 子进程后处理                                         │
│     lbm_post.vtk_reader → 读取 output/fluid_*.npz                   │
│     lbm_post.plot       → 生成 PNG 图像                              │
│     lbm_post.analysis   → 计算阻力/升力、体积平均量等                 │
└─────────────────────────────────────────────────────────────────────┘
```

### 5.2 Rust ↔ C++ 调用（FFI）

`bindings/src/lib.rs` 通过 C ABI 调用 C++ 核心库：

```
Rust orchestrator
    │
    ├─ LbmGrid::new(nx, ny, nz, model)
    │       └─→ C ABI: lbm_grid_new()  →  C++ LatticeGrid（堆分配）
    │
    ├─ LbmSolver::new(&mut grid, omega, cm)
    │       └─→ C ABI: lbm_solver_new() → C++ Solver（堆分配）
    │
    ├─ solver.step(&mut grid)             ← 每个时间步执行碰撞+迁移+边界条件+宏观量更新
    │       └─→ C ABI: lbm_solver_step()
    │               └─→ Solver::step()
    │                     ├─ collide()              ← BGK/MRT 碰撞（使用上步末尾 ρ/u）
    │                     ├─ stream()               ← 周期性迁移 + 第一次 compute_macroscopic()
    │                     ├─ apply_boundary_conds() ← 反弹/Zou-He 覆盖幽灵方向
    │                     └─ compute_macroscopic()  ← 第二次（边界节点 ρ/u 修正）
    │
    └─ grid.rho(idx) / .ux(idx) / .uy(idx)
            └─→ C ABI: lbm_grid_rho/ux/uy() ← 读取格点流场数据
```

`bindings/build.rs` 在 Rust 编译期自动调用 cmake 构建 `liblbm_core.a`，并通过 `cargo:rustc-link-lib=static=lbm_core` 链接。

### 5.3 Rust → Python 子进程调用

Rust 主控使用 `std::process::Command` 以子进程方式调用 Python 脚本：

```
main() 主控
    │
    ├─ [可选] 预处理阶段
    │   run_python_subprocess(interpreter, pre_script, [config_path])
    │       └─→ python3 <pre_script> configs/my_run.toml
    │
    ├─ [仿真循环]
    │
    └─ [可选] 后处理阶段
        run_python_subprocess(interpreter, post_script, [output_dir])
            └─→ python3 <post_script> output/lid_cavity
```

**接口规范**：
- 预处理脚本接收一个位置参数：TOML 配置文件路径。
- 后处理脚本接收一个位置参数：输出目录路径。
- 脚本退出码非 0 时，Rust 主程序报错退出。

### 5.4 Rust → Python FFI 调用（pyo3）

启用 `python-ffi` Cargo 特性后，Rust 通过 pyo3 在进程内直接调用 Python：

```
main() [需要 --features python-ffi]
    │
    ├─ python_bridge::add_python_path("python/")
    │       └─→ pyo3: sys.path.insert(0, "python/")
    │
    ├─ python_bridge::markers_from_geometry("circle", 50.0, 40.0, 10.0, 64)
    │       └─→ pyo3: lbm_pre.bridge.geometry_markers_raw("circle", ...)
    │               → 返回 (Vec<f64>, Vec<f64>, Vec<f64>)  ← 无文件
    │
    └─ python_bridge::plot_field(&rho, &ux, &uy, nx, ny, step, time,
                                  out_dir, "velocity_magnitude")
            └─→ pyo3: lbm_post.bridge.plot_field_raw(rho_list, ux_list, uy_list, ...)
                    → numpy reshape → matplotlib 绘图 → 保存 PNG  ← 无 NPZ 中间文件
```

**数据传递方式**：Rust `&[f64]` 切片 → `pyo3::types::PyList` → Python 函数参数。NumPy 在 Python 侧负责 reshape（`np.asarray(rho).reshape(ny, nx)`），Rust 侧无需了解 NumPy 内部格式。

### 5.5 Python 独立使用路径（无 Rust）

Python 模块设计为可独立运行，无需 Rust 程序：

```
用户 Python 脚本
    │
    ├─ from lbm_pre.config_gen import SolverConfig
    │   SolverConfig.lid_driven_cavity().write("configs/my.toml")
    │
    ├─ from lbm_pre.geometry import circle_markers, write_markers_csv
    │   markers = circle_markers(50, 40, 10, 128)
    │   write_markers_csv(markers, "markers.csv")     ← 生成文件
    │
    ├─ from lbm_pre.bridge import geometry_markers_raw
    │   x, y, ds = geometry_markers_raw("circle", 50, 40, 10, 128)  ← 无文件
    │
    ├─ from lbm_post.vtk_reader import NpzReader
    │   snap = NpzReader("output/").last()
    │
    ├─ from lbm_post.plot import plot_velocity_magnitude, save_figure
    │   fig, _ = plot_velocity_magnitude(snap)
    │   save_figure(fig, "vel_mag.png")
    │
    └─ from lbm_post.bridge import plot_field_raw
        plot_field_raw(rho, ux, uy, nx, ny, step, time, "output/", "vorticity")
```

## 六、数据传输格式要求

### 6.1 TOML 配置文件（Python → Rust）

Python 端用 `lbm_pre.config_gen.SolverConfig.write()` 生成，Rust 端用 `Config::from_file()` 解析。

完整结构：

```toml
[simulation]
n_steps        = 10000          # 总时间步数
dt             = 1.0            # 时间步长（格子单位）
lattice_model  = "D2Q9"         # "D2Q9" | "D3Q19" | "D3Q27"
collision_model = "MRT"         # "BGK" | "MRT"

[fluid]
nx   = 100                      # x 方向格点数
ny   = 100                      # y 方向格点数
nz   = 1                        # z 方向格点数（2D 仿真设 1）
nu   = 0.01                     # 运动粘度（格子单位，建议 0.05 ~ 0.5）
rho0 = 1.0                      # 初始均匀密度

  [[fluid.boundary_conditions]]
  bc_type = "zou_he_velocity"   # 见下方 bc_type 取值表
  face    = "north"             # "west" | "east" | "south" | "north" | "bottom" | "top"
  ux      = 0.1                 # 边界 x 速度（zou_he_velocity / guo_extrapolation 有效）
  uy      = 0.0
  rho     = 1.0                 # 边界密度（zou_he_pressure 有效；guo_extrapolation 中 rho≤0 则外推）

[structure]                     # 可选，FSI 结构参数
young_modulus  = 1.0e3
second_moment  = 1.0e-6
density        = 1.5
area           = 0.01
length         = 0.3
n_elements     = 10

[ibm]                           # 可选，IBM 几何参数
geometry   = "circle"           # "circle" | "filament"
x0         = 50.0               # 圆心/起点 x（格子单位）
y0         = 40.0               # 圆心/起点 y
size       = 10.0               # 半径（circle）/ 长度（filament）
n_markers  = 64                 # 拉格朗日标记点数
delta_kernel = "four_point"     # "two_point" | "four_point"

[output]
write_interval     = 500        # 快照输出间隔（高频原生写出）
directory          = "output/lid_cavity"
format             = "npz"      # ★ 输出格式："npz"（默认）| "tecplot_asc" | "tecplot_bin"
plot_interval      = 2000       # Python FFI 云图间隔（可选，需 --features python-ffi）
enable_csv_monitor = true       # 每步追加 CSV 一行（轻量时序输出）

[python]                        # 可选
interpreter = "python3"         # Python 可执行文件路径
pre_script  = "scripts/pre.py"  # 预处理脚本（子进程模式，可省略）
post_script = "scripts/post.py" # 后处理脚本（子进程模式，可省略）
pythonpath  = "python"          # 追加到 sys.path，使 lbm_pre/lbm_post 可导入

[parallel]                      # ★ 可选，并行配置
omp_num_threads = 8             # OpenMP 线程数（0 = 使用系统默认，即全部物理核心）

[mpi]                           # ★ 可选，MPI 域分解配置
# 模式一：一维 Y 切片（默认，适合 ny >> nx 的网格）
mode = "1d_y"

# 模式二：二维 XY 块分解（适合接近方形的网格）
# mode      = "2d_xy"
# nx_blocks = 4    # X 方向进程数（须满足 nx_blocks * ny_blocks == mpirun -n N）
# ny_blocks = 2    # Y 方向进程数

# 模式三：多网格独立模式（每进程独立仿真，输出到 output/rank_N/）
# mode = "multi_grid"
```

#### 参数约束

| 参数 | 类型 | 约束 |
|------|------|------|
| `nu` | float64 | 建议 0.05 ≤ ν ≤ 0.5（保证 τ ∈ (0.5, 2)） |
| `n_steps` | uint64 | ≥ 0 |
| `write_interval` | uint64 | ≥ 1 |
| `lattice_model` | string | "D2Q9" / "D3Q19" / "D3Q27" |
| `collision_model` | string | "BGK" / "MRT" |
| `format` | string | "npz" / "tecplot_asc" / "tecplot_bin" |
| `parallel.omp_num_threads` | uint32 | 0 = 系统默认；正整数 = 强制指定线程数 |
| `mpi.mode` | string | "1d_y"（默认）/ "2d_xy" / "multi_grid" |
| `mpi.nx_blocks` | uint32 | mode="2d_xy" 时有效；nx_blocks × ny_blocks == nprocs |
| `mpi.ny_blocks` | uint32 | 同上 |

#### `bc_type` 取值表

| 取值 | C++ 枚举 | 类型 | 说明 |
|------|----------|------|------|
| `"bounce_back"` | `BounceBack` | **固壁 BC** ✦ | 半步长反弹，无滑移固壁，**2 阶精度**（推荐） |
| `"bounce_back_full_way"` | `BounceBackFullWay` | **固壁 BC** ✦ | 全步长反弹，无滑移固壁，1 阶精度 |
| `"zou_he_velocity"` | `ZouHe_Velocity` | 流体进/出口 BC | Zou-He 速度 BC，规定 ux/uy，4 面均支持 |
| `"zou_he_pressure"` | `ZouHe_Pressure` | 流体进/出口 BC | Zou-He 压力 BC，规定 rho，4 面均支持 |
| `"fully_developed"` | `FullyDeveloped` | 流体进/出口 BC | 充分发展出口（零法向梯度拷贝），适合通道出口 |
| `"free_outlet"` | `FreeOutlet` | 流体进/出口 BC | 自由出口（与 `fully_developed` 等价） |
| `"guo_extrapolation"` | `Guo_Extrapolation` | 流体进/出口 BC | 郭照立非平衡外推（Guo 2002），通用速度/压力 BC |
| `"periodic"` | `Periodic` | 流体进/出口 BC | 周期边界（已由流式迁移隐式处理，此处仅标注） |

> ✦ **固壁 BC**：仅 `bounce_back` 和 `bounce_back_full_way` 属于固壁 BC；其余均为流体进/出口 BC。

> **角点修正规则**：在所有面 BC 完成后，求解器自动对 4 个角节点（SW/SE/NW/NE）施加半步长反弹修正。修正条件为：该角节点的**两个相邻面中至少有一面是固壁 BC**（`bounce_back` 或 `bounce_back_full_way`）。若两相邻面均为流体进/出口 BC（如 `fully_developed`、`free_outlet`、`zou_he_pressure` 等），则跳过该角节点，避免对开放出口角点强制施加物理上不正确的 u = 0 约束。

> **详细推导文档**：参见 `docs/边界条件推导.md`，包含所有边界条件的完整数学推导、公式验证和使用指南。

## 十一、插件扩展架构

本节说明如何利用内置的插件系统为框架添加以下四类扩展，而**无需修改任何已有代码**：

1. 新边界条件
2. 新网格划分/处理方式（含自适应网格）
3. 新流体动网格 / 固体结构运动模型
4. 新柔性结构求解器

### 插件还有用吗？——与内置 BC 的关系

添加边界条件、运动、网格等功能**既可以通过 TOML 内置配置，也可以通过插件系统**，二者分别针对不同复杂度的场景：

| 方法 | 适用场景 | 配置方式 | 是否需要写代码 |
|------|----------|----------|--------------|
| **TOML `[[fluid.boundary_conditions]]`** | 固定静态边界（半步/全步反弹、Zou-He 速度/压力、充分发展出口、Guo 外推）| `bc_type = "..."`, `face = "..."` | 不需要 |
| **`IBoundaryPlugin`** | 动态/非标准边界（对流出口、海绵层、NRBC、周期性 + 施力组合）| `[plugins] boundary = "..."` | 需要（C++ 或 Rust） |
| **`IMotionPlugin`** | 运动壁面、振荡固体、ALE | `[plugins] motion = "..."` | 需要 |
| **`IMeshPlugin`** | 自适应细化、拉伸/非均匀网格 | `[plugins] mesh = "..."` | 需要 |
| **`IFlexibleSolverPlugin`** | 替换内置 Euler-Bernoulli 梁（板壳、协转梁）| `[plugins] flexible = "..."` | 需要 |

**结论**：内置 BC 现已覆盖绝大多数经典基准（方腔、管道、绕柱、通道流）所需的全部边界格式。只有当你需要**非标准物理行为**（对流出口、运动几何、自适应网格、替换结构求解器）时，才需要实现并注册插件。

---

### 11.1 设计原则

插件系统遵循**开闭原则（Open-Closed Principle）**：核心求解器对修改封闭，对扩展开放。

```
┌─────────────────────────────────────────────────────────────────┐
│                     插件系统分层架构                             │
│                                                                 │
│  C++ 接口层（纯虚类，headers-only）                              │
│  ┌──────────────────┐  ┌───────────────┐                       │
│  │ IBoundaryPlugin  │  │ IMeshPlugin   │                       │
│  │ IMotionPlugin    │  │ IFlexibleSolverPlugin                 │
│  └──────────────────┘  └───────────────┘                       │
│            ↑                    ↑                               │
│         子类化               子类化                              │
│  ┌──────────────────────────────────────────┐                  │
│  │           PluginRegistry (singleton)     │                  │
│  │  boundary_  mesh_  motion_  flexible_    │                  │
│  │  apply_boundary() adapt_mesh()  ...      │                  │
│  └──────────────────────────────────────────┘                  │
│            ↑                                                    │
│   C ABI 适配（plugin_registry.cpp）                             │
│   lbm_set_plugins(boundary_fn, mesh_fn, motion_fn, flex_fn)    │
│            ↑                                                    │
│   Rust 安全封装（bindings/src/lib.rs）                          │
│   register_plugins(PluginCallbacks { boundary_fn: Some(...) }) │
│            ↑                                                    │
│   TOML 配置（orchestrator/src/config.rs）                       │
│   [plugins]  boundary = "..."  mesh = "..."  ...               │
└─────────────────────────────────────────────────────────────────┘
```

**插件调用顺序**（在每个时间步内，v0.1.1 修复后的完整流程）：

```
IMotionPlugin::update()           ← 步骤前：更新固体/标记点位置
  → Solver::step()                ← 核心 LBM 步骤（含内置 BC）：
  │     collide()                    碰撞（BGK/MRT）
  │     stream()                     流式迁移 + 第一次宏观量更新（含幽灵值）
  │     apply_boundary_conditions()  内置 BC（反弹/Zou-He）覆盖幽灵方向
  │     compute_macroscopic()        第二次宏观量更新（边界节点得到正确 ρ/u）
  → IBoundaryPlugin::apply()     ← 迁移后：插件自定义扩展边界条件
  → IMeshPlugin::adapt()         ← 迁移后：网格自适应
  → IFlexibleSolverPlugin::step() ← 迁移后：柔性结构推进
```

> **注意：** `IBoundaryPlugin::apply()` 在 `Solver::step()` 之后执行，即在内置 BC
> 已处理完毕之后才调用插件扩展点。若插件需要依赖边界节点的正确 ρ/u，此时已
> 由第二次 `compute_macroscopic()` 保证。

### 11.2 扩展点一：新增边界条件（IBoundaryPlugin）

#### 接口文件
`core/include/plugins/boundary_plugin.hpp`

#### C++ 实现步骤

```cpp
// my_bc_plugin.hpp
#include "plugins/boundary_plugin.hpp"
#include "lbm/lattice.hpp"

class ConvectiveOutlet : public lbm::IBoundaryPlugin {
public:
    void apply(lbm::LatticeGrid& grid, int step) override {
        // 在 East 面施加对流出口 BC
        // grid.f 包含迁移后的分布函数，直接修改即可
        const int nx = grid.nx;
        const int ny = grid.ny;
        for (int j = 0; j < ny; ++j) {
            int n = grid.idx(nx - 1, j);
            // ... 对流出口公式 ...
        }
    }
    const char* name() const override { return "convective_outlet"; }
};
```

#### 注册方式（C++ 侧）

```cpp
#include "plugins/plugin_registry.hpp"
ConvectiveOutlet my_bc;
lbm::PluginRegistry::instance().set_boundary_plugin(&my_bc);
```

#### 注册方式（Rust 侧）

```rust
use lbm_bindings::{PluginCallbacks, register_plugins};

unsafe extern "C" fn my_bc_fn(
    grid: *mut std::ffi::c_void,
    step: i32,
    _data: *mut std::ffi::c_void,
) {
    // 将 grid 转型后应用自定义 BC
    let _ = (grid, step);
}

let mut cbs = PluginCallbacks::default();
cbs.boundary_fn = Some(my_bc_fn);
register_plugins(cbs);
```

#### TOML 配置

```toml
[plugins]
boundary = "convective_outlet"  # 仅作记录日志用，不自动加载共享库
```

### 11.3 扩展点二：新增网格划分处理方式（IMeshPlugin）

#### 接口文件
`core/include/plugins/mesh_plugin.hpp`

#### 使用场景
- 自适应均匀加密（局部细化）
- z 方向拉伸格子（非均匀间距）
- Overset / Chimera 嵌套网格
- 区域分解重分配（负载均衡）

#### C++ 实现步骤

```cpp
#include "plugins/mesh_plugin.hpp"

class AdaptiveRefinement : public lbm::IMeshPlugin {
public:
    void initialize(lbm::LatticeGrid& grid,
                    const void* cfg) override {
        // 读取 cfg 中的细化参数，初始化辅助数据结构
    }

    void adapt(lbm::LatticeGrid& grid, int step) override {
        if (step % refine_interval_ == 0) {
            // 1. 计算误差指示器（涡量梯度等）
            // 2. 标记需要细化/粗化的格点
            // 3. 重新分配 grid.f、grid.rho、grid.u 数组
        }
    }

    const char* name() const override { return "adaptive_uniform"; }

private:
    int refine_interval_ = 500;
};
```

#### 关键数据访问

- `grid.f[node * q + direction]` — 分布函数（可直接修改）
- `grid.rho[node]`、`grid.u[node * dim + d]` — 宏观量
- 网格尺寸通过 `grid.nx / ny / nz` 访问；调整尺寸需同步修改 `grid.f.resize()`

### 11.4 扩展点三：新增流体动网格 / 固体结构运动（IMotionPlugin）

#### 接口文件
`core/include/plugins/motion_plugin.hpp`

#### 使用场景
- 旋转圆柱（prescribed sine/cosine 运动）
- 直升机旋翼（Chimera + 刚体 6-DOF）
- 任意拉格朗日-欧拉（ALE）滑移面
- 柔性叶片的刚体整体平移

#### 方法签名

```cpp
void update(lbm::LatticeGrid& grid,
            ibm::MarkerSet* markers,   // 可为 nullptr（纯 LBM 无 IBM 时）
            double dt,
            int step) override;
```

#### C++ 实现骨架

```cpp
#include "plugins/motion_plugin.hpp"
#include "ibm/marker.hpp"
#include <cmath>

class PrescribedSineMotion : public lbm::IMotionPlugin {
public:
    void update(lbm::LatticeGrid& /*grid*/,
                ibm::MarkerSet* markers,
                double dt, int step) override
    {
        if (!markers) return;
        const double t = step * dt;
        const double dy = amplitude_ * std::sin(2.0 * M_PI * freq_ * t) * dt;
        for (auto& m : markers->markers) {
            m.y += dy;
            m.y0 = m.y;   // 更新参考位置（用于 IBM 力计算）
        }
    }
    const char* name() const override { return "prescribed_sine"; }
private:
    double amplitude_ = 2.0;
    double freq_      = 0.05;
};
```

#### 注意事项
- `markers` 在无 IBM 场景下为 `nullptr`，**必须先判空**。
- 移动欧拉格点（ALE）时需同步更新 `grid.u` 中的网格速度，以便在 Guo 外力修正中正确处理相对速度。

### 11.5 扩展点四：新增柔性结构求解器（IFlexibleSolverPlugin）

#### 接口文件
`core/include/plugins/flexible_plugin.hpp`

#### 使用场景
- Kirchhoff-Love 薄板（替代 Euler-Bernoulli 梁）
- 共旋转（Co-rotational）大变形梁
- 有限体积膜（3-D 柔性表面）
- 简化降阶模型（POD-ROM 快速代理）
- 外部 FEM 程序耦合（如 Calculix、Code_Aster）

#### 方法签名

```cpp
void step(ibm::MarkerSet& markers, double dt, int step_idx) override;
```

**入口状态**：`markers.markers[i].{ux, uy}` 已由速度插值填充（流体 → 结构的速度耦合）。  
**出口要求**：`markers.markers[i].{x, y, fx, fy}` 必须更新（新位置和 IBM 力密度），以供后续 `spread_force()` 使用。

#### C++ 实现骨架

```cpp
#include "plugins/flexible_plugin.hpp"

public:

            m.fy = restoring_fy_[i];
            ++i;
        }
    }
    const char* name() const override { return "kirchhoff_love_plate"; }
private:

    void solve_plate(double dt) { /* FEM assembly + solve */ }
```

```rust
use lbm_bindings::{LatticeModel, CollisionModel, LbmGrid, LbmSolver,
                   PluginCallbacks, register_plugins};

// 定义自定义边界条件回调（C ABI 兼容）
unsafe extern "C" fn my_open_bc(
    grid_ptr: *mut std::ffi::c_void,
    step: i32,
    _data: *mut std::ffi::c_void,
) {
    // 将 grid_ptr 转型为 *mut lbm::LatticeGrid 并应用 BC
    // （需要 unsafe + C++ 布局知识，建议封装为 C++ 子类后通过 C ABI 调用）
    let _ = (grid_ptr, step);
}

// 在仿真循环前注册
let mut cbs = PluginCallbacks::default();

register_plugins(cbs);  // 写入全局 PluginRegistry 单例

// 此后每次 solver.step() 内部会自动调用 my_open_bc

    solver.step_n(&mut grid, step, 1.0);
}
```

新增任意插件时，按以下顺序操作：

### 12.2 `cargo build` 执行逻辑全流程

当在项目根目录执行 `cargo build` 时，Cargo 按下图顺序处理**工作空间（workspace）**中的每个 crate：

```
cargo build
    │
    ├─ 读取  Cargo.toml（workspace）
    │         members = ["orchestrator", "bindings"]
    │
    ├─① 编译 lbm-bindings crate（bindings/）
    │   │
    │   ├─ 检测到 [package] links = "lbm_core"
    │   │  → 必须执行 bindings/build.rs（构建脚本）
    │   │
    │   ├─② 运行 bindings/build.rs
    │   │   │
    │   │   ├─ cmake::Config::new(repo_root)        ← 指定顶层 CMakeLists.txt 所在目录
    │   │   │   .define("BUILD_TESTS", "OFF")
    │   │   │   .define("ENABLE_MPI",    "OFF")     ← 默认关闭，见 §12.4
    │   │   │   .define("ENABLE_OPENMP", "OFF")
    │   │   │   .build()                            ← 触发 cmake configure + make
    │   │   │
    │   │   │   cmake 执行顺序（见 §12.3）：
    │   │   │     ③ CMakeLists.txt（顶层）          ← 全局选项、编译器配置
    │   │   │     ④ core/CMakeLists.txt             ← 编译 lbm_core.a
    │   │   │     （core/tests/CMakeLists.txt 因 BUILD_TESTS=OFF 被跳过）
    │   │   │
    │   │   ├─ println!("cargo:rustc-link-search=native=.../lib")
    │   │   │   → 告诉 rustc: 在该目录寻找 .a 文件
    │   │   │
    │   │   ├─ println!("cargo:rustc-link-lib=static=lbm_core")
    │   │   │   → 告诉 rustc: 链接 liblbm_core.a
    │   │   │
    │   │   ├─ println!("cargo:rustc-link-lib=stdc++")   ← Linux；macOS→c++；Windows 跳过
    │   │   │   → 链接 C++ 标准库（平台相关）
    │   │   │
    │   │   └─ （若 LBM_ENABLE_MPI=ON）解析 <dst>/mpi_link.txt
    │   │       → println!("cargo:rustc-link-search=native=<MPI 库目录>")
    │   │       → println!("cargo:rustc-link-lib=mpi")   ← Windows MS-MPI 为 msmpi
    │   │
    │   └─ 编译 bindings/src/lib.rs
    │       → 生成 liblbm_bindings.rlib
    │
    └─③ 编译 lbm-ibm-fsi crate（orchestrator/）
        │  依赖 lbm-bindings（已在上一步编译完成）
        │
        ├─ 编译 orchestrator/src/config.rs
        ├─ 编译 orchestrator/src/output.rs
        ├─ 编译 orchestrator/src/python_bridge.rs
        └─ 编译 orchestrator/src/main.rs
            → 最终链接：lbm_ibm_fsi + lbm_bindings + liblbm_core.a + libstdc++
            → 生成可执行文件 target/debug/lbm-ibm-fsi
```

> **关键机制**：`[package] links = "lbm_core"` 告诉 Cargo 该 crate 负责链接名为 `lbm_core` 的原生库，整个 workspace 中只允许一个 crate 声明链接同一个原生库名称，从而避免重复链接冲突。

### 12.3 `build.rs` 逐行解析

文件位置：`bindings/build.rs`

```rust
fn main() {
    // ① 获取 bindings/ 目录的绝对路径
    let manifest_dir = PathBuf::from(env!("CARGO_MANIFEST_DIR"));
    // ② 向上一级 = 项目根目录（包含顶层 CMakeLists.txt）
    let repo_root = manifest_dir.parent().unwrap();

    // ② 推断 cmake 构建类型（与 Cargo OPT_LEVEL 对齐，防止 MSVC 运行时库冲突）
    // OPT_LEVEL=0 → cargo build（Debug）；OPT_LEVEL≥1 → cargo build --release（Release）
    let cmake_build_type = if std::env::var("OPT_LEVEL").unwrap_or_default() == "0" {
        "Debug"
    } else {
        "Release"
    };

    // ③ 调用 cmake crate 驱动 CMake 构建
    //    cmake::Config::new(src_dir) 指定 CMake 源码树根目录
    let dst = cmake::Config::new(repo_root)
        // 关闭 C++ 测试构建，加速 Rust 构建链路
        .define("BUILD_TESTS", "OFF")
        // MPI/OpenMP/CUDA：Rust 侧默认关闭（避免 CI 环境依赖问题）；
        // 若需要，设置环境变量 LBM_ENABLE_MPI=ON / LBM_ENABLE_OPENMP=ON 后重新构建
        .define("ENABLE_MPI",    std::env::var("LBM_ENABLE_MPI")
                                    .unwrap_or_else(|_| "OFF".into()))
        .define("ENABLE_OPENMP", std::env::var("LBM_ENABLE_OPENMP")
                                    .unwrap_or_else(|_| "OFF".into()))
        .define("ENABLE_CUDA",   std::env::var("LBM_ENABLE_CUDA")
                                    .unwrap_or_else(|_| "OFF".into()))
        .define("CMAKE_BUILD_TYPE", cmake_build_type)  // 单配置生成器（Ninja）使用此值
        // .build() 等价于：
        //   cmake <repo_root> -DBUILD_TESTS=OFF ... -B <out_dir>/build
        //   cmake --build <out_dir>/build
        // 返回值 dst = CMake install prefix（Cargo 管理的临时目录）
        .build();

    // ④ 告知 rustc 在 cmake install prefix 下的 lib/ 目录中查找链接库
    println!("cargo:rustc-link-search=native={}/lib", dst.display());

    // ⑤ 静态链接 liblbm_core.a
    println!("cargo:rustc-link-lib=static=lbm_core");

    // ⑥ 链接 C++ 标准库（平台判断）
    // 使用运行时环境变量（目标平台）而非编译时 cfg!（宿主平台），支持交叉编译
    let target_os = std::env::var("CARGO_CFG_TARGET_OS").unwrap_or_default();
    match target_os.as_str() {
        "macos" | "ios" => println!("cargo:rustc-link-lib=c++"),   // Apple Clang → libc++
        "windows"       => {}                                        // MSVC 自动链接 CRT，无需声明
        _               => println!("cargo:rustc-link-lib=stdc++"), // Linux/FreeBSD → libstdc++
    }

    // ⑦ 当 MPI 启用时链接 MPI 库
    // CMakeLists.txt 在构建时将 MPI 链接信息写入 <dst>/mpi_link.txt，
    // 此处解析该文件并向 rustc 发出链接搜索路径 / 库名指令。
    // 若不这样做，Rust 最终链接步骤会因 MPI 符号未解析而失败
    // （Windows: LNK1120，Linux: undefined symbol）。
    let mpi_val = std::env::var("LBM_ENABLE_MPI").unwrap_or_else(|_| "OFF".into());
    let mpi_enabled = matches!(mpi_val.to_uppercase().as_str(), "ON" | "1" | "TRUE" | "YES");
    if mpi_enabled {
        let mpi_file = dst.join("mpi_link.txt");
        if mpi_file.exists() {
            let info = std::fs::read_to_string(&mpi_file).unwrap();
            for line in info.lines() {
                let line = line.trim();
                if line.is_empty() { continue; }
                if let Some(dir) = line.strip_prefix("search:") {
                    println!("cargo:rustc-link-search=native={}", dir);
                } else if let Some(lib_spec) = line.strip_prefix("lib:") {
                    emit_mpi_lib(lib_spec);
                }
            }
        }
    }

    // ⑧ 增量构建守卫：以下路径发生变化时重新执行 build.rs
    println!("cargo:rerun-if-changed=../core/src");
    println!("cargo:rerun-if-changed=../core/include");
    println!("cargo:rerun-if-env-changed=LBM_ENABLE_MPI");
    println!("cargo:rerun-if-env-changed=LBM_ENABLE_OPENMP");
    println!("cargo:rerun-if-env-changed=LBM_ENABLE_CUDA");
}

/// 将 CMake 给出的 MPI 库规格转换为 `cargo:rustc-link-*` 指令。
///
/// CMake FindMPI 模块通常给出完整路径（如 `/usr/lib/libmpi.so`、
/// `C:/Program Files (x86)/Microsoft SDKs/MPI/Lib/x64/msmpi.lib`）
/// 或纯库名（如 `mpi`、`msmpi`）。
fn emit_mpi_lib(spec: &str) {
    let p = std::path::Path::new(spec);
    if p.is_absolute() {
        // 完整路径：将目录加入搜索路径，将文件茎作为库名
        if let Some(parent) = p.parent() {
            if !parent.as_os_str().is_empty() {
                println!("cargo:rustc-link-search=native={}", parent.display());
            }
        }
        if let Some(stem) = p.file_stem() {
            let name = stem.to_string_lossy();
            // 去掉 Unix 惯例的 "lib" 前缀（例如 "libmpi" → "mpi"）
            let lib_name = name.strip_prefix("lib").unwrap_or(&name);
            println!("cargo:rustc-link-lib={}", lib_name);
        }
    } else {
        // 纯库名，直接透传（例如 "msmpi"）
        println!("cargo:rustc-link-lib={}", spec);
    }
}
```

**`cargo:rerun-if-changed` 机制**：Cargo 在每次构建时比较文件修改时间。只要 `core/src/` 或 `core/include/` 下有文件发生变动，就会重新运行 `build.rs`，从而触发增量 CMake 重新编译。没有变化时 `lbm_core.a` 直接从缓存中读取，无需重新编译 C++ 代码。

### 12.4 各 CMakeLists.txt 执行顺序与作用

CMake 构建按如下顺序处理三个 CMakeLists.txt 文件：

---

#### 第 1 步：`CMakeLists.txt`（顶层，项目根目录）

```
作用：全局编译环境配置
触发时机：cmake::Config::new(repo_root).build() 首先处理此文件
```

| 指令 | 说明 |
|------|------|
| `cmake_minimum_required(VERSION 3.20)` | 检查 CMake 版本，低于 3.20 立即报错 |
| `project(lbm_ibm_fsi ...)` | 声明项目名称、版本、使用的语言（CXX） |
| `set(CMAKE_CXX_STANDARD 17)` | 强制所有子目标使用 C++17 |
| `option(ENABLE_MPI ...)` | 定义 `ENABLE_MPI` 开关，默认 ON；`build.rs` 传入 `OFF` 以禁用 |
| `option(ENABLE_OPENMP ...)` | 同上，OpenMP 并行开关 |
| `option(ENABLE_CUDA ...)` | CUDA GPU 加速开关，默认 OFF |
| `option(BUILD_TESTS ...)` | 是否编译 C++ 单元测试，`build.rs` 传入 `OFF` |
| `add_compile_options(-O3 -march=native ...)` | GCC/Clang 下启用 O3 优化和本机指令集 |
| `set(CMAKE_MSVC_RUNTIME_LIBRARY "MultiThreadedDLL")` | **MSVC 专用**：强制所有配置使用 `/MD`，防止与 Rust 链接时出现运行时库冲突 |
| `find_package(MPI REQUIRED)` | 若 `ENABLE_MPI=ON`，查找系统 MPI 并报错退出（若未找到） |
| `file(WRITE ... mpi_link.txt ...)` | 若 `ENABLE_MPI=ON`，将 MPI 库路径写入 `<build>/mpi_link.txt`；`build.rs` 读取此文件向 rustc 发出链接指令，解决 Windows LNK1120 / Linux undefined symbol |
| `install(FILES mpi_link.txt ...)` | 将 `mpi_link.txt` 安装到 cmake install prefix 根目录（`build.rs` 的 `dst` 路径） |
| `find_package(OpenMP REQUIRED)` | 若 `ENABLE_OPENMP=ON`，查找 OpenMP 并报错退出 |
| `add_subdirectory(core)` | **递归进入 `core/CMakeLists.txt`（第 2 步）** |
| `add_subdirectory(core/tests)` | 若 `BUILD_TESTS=ON` 才递归进入测试 CMakeLists.txt（第 3 步，Rust 构建时跳过） |

---

#### 第 2 步：`core/CMakeLists.txt`（核心库）

```
作用：编译所有 C++ 计算代码，生成静态库 liblbm_core.a
触发时机：顶层 add_subdirectory(core) 触发
```

| 指令 | 说明 |
|------|------|
| `set(CORE_SOURCES ...)` | 列出需要编译的 9 个 `.cpp` 源文件（LBM / IBM / FSI / CAPI / Plugin） |
| `add_library(lbm_core STATIC ...)` | 将上述源文件编译并打包为静态库 `liblbm_core.a` |
| `target_include_directories(lbm_core PUBLIC ...)` | 向所有依赖 `lbm_core` 的目标暴露 `core/include/` 头文件路径 |

### 12.8 Cargo 缓存与增量编译原理

Cargo 通过以下机制决定是否重新编译：

1. **Rust 源文件变化**：Cargo 对每个 `.rs` 文件生成内容哈希；若哈希不变则不重编。

2. **`build.rs` 重运行判断**：`build.rs` 通过以下语句声明依赖：
   ```rust
   println!("cargo:rerun-if-changed=../core/src");
   println!("cargo:rerun-if-changed=../core/include");
   println!("cargo:rerun-if-env-changed=LBM_ENABLE_MPI");
   ```
   Cargo 记录这些路径的最后修改时间戳。只要 `core/src/` 或 `core/include/` 下有文件变动，或环境变量 `LBM_ENABLE_MPI` / `LBM_ENABLE_OPENMP` 发生变化，才重新运行 `build.rs`（进而触发增量 CMake 编译）。

3. **CMake 增量编译**：CMake 自身记录每个 `.cpp` 文件的依赖关系（通过 `-MD` 编译标志生成 `.d` 文件）。只有被修改的 `.cpp` 及其依赖的头文件对应的目标文件会被重新编译，最后重新打包成 `liblbm_core.a`。

4. **链接阶段**：只有 `liblbm_core.a` 或任意 `.rlib` 发生变化时，最终链接步骤才会重新执行。

典型增量构建时间（修改一个 `.cpp` 文件后）：

```
重新编译该 .cpp → 更新 liblbm_core.a → 重新链接 lbm-ibm-fsi
约 5–15 秒（取决于文件大小和机器性能）
```

### 12.9 常见问题排查

| 症状 | 可能原因 | 解决方法 |
|------|----------|----------|
| `cmake: command not found` | CMake 未安装 | `sudo apt-get install cmake` |
| `MPI not found` | OpenMPI/MPICH 缺失 | `sudo apt-get install libopenmpi-dev` 或设置 `LBM_ENABLE_MPI=OFF` |
| `OpenMP not found` | 编译器不支持 OpenMP | `sudo apt-get install libomp-dev` 或设置 `LBM_ENABLE_OPENMP=OFF` |

#### 新增：MgTree AMR 延拓/限制算子（`mg_prolong_rho_u` / `mg_restrict_rho_u`）

**文件：** `core/include/lbm/mg_tree.hpp`、`core/src/lbm/mg_tree.cpp`、`core/src/capi/lbm_capi.cpp`

实现了自适应网格加密（AMR）的粗-细网格数据传递算子：

- **`mg_prolong_rho_u(coarse, fine)`（延拓）**：从粗网格通过双线性插值将宏观量 ρ/u 传递到细网格。
  坐标映射：细节点 `(if, jf)` 在粗坐标系中的位置为 `px = fine.extent.x_start + if / r`，

- **`mg_restrict_rho_u(fine, coarse)`（限制）**：将细网格 `r×r` 个节点的 ρ/u 体积平均写回对应粗节点，
  保证质量守恒的平均投影。
- **C API**：`lbm_mg_prolong_rho_u(coarse_node, fine_node)` / `lbm_mg_restrict_rho_u(fine_node, coarse_node)`，返回 0（成功）或 -1（参数错误）。

1. **`MgNode::decomp`：`void*` → `std::variant<std::monostate, MpiDecomp2D*, MpiDecomp3D*>`**
   提供编译期类型安全：可通过 `std::holds_alternative<MpiDecomp2D*>()` 区分 2D/3D 域分解，

3. **`MgTree::add_level()` 新增 `refine_ratio` 上界检查**
   `refine_ratio > 1024` 时抛出 `std::invalid_argument`，避免隐式溢出。

4. **消除 `collide_bgk()` / `collide_mrt()` 中的重复幽灵层跳过逻辑**

#### Bug Fix：`plot_velocity_magnitude` / `plot_vorticity` 对近均匀流场放大机器精度噪声

**文件：** `python/lbm_post/plot.py`

**问题描述：**

在"速度入口 + 三面充分发展出口"（`velocity_inlet_free_outlet.toml`）配置下，稳态
物理解为全域均匀来流（|u| ≈ 0.05，uy ≈ 0）。经过数万步迭代后，峰-峰速度变化量
降至机器精度水平（≤ 10⁻¹⁴），物理上完全正确。

然而 `plot_velocity_magnitude` 中的 `ax.contourf(x, y, mag, ...)` 在未指定
`vmin`/`vmax` 时使用 matplotlib 自动色标，会将这一几乎为零的变化量拉伸至整个颜色
范围，产生两类视觉假象：

1. **速度反弹（假象）**：色标自动随机器噪声的方向翻转，使第 10001 步左侧最高、
   第 18001 步右侧最高，看似速度场逆向流动（实际变化量 < 2×10⁻¹²）。
2. **树状条纹（假象）**：第 22001 步及之后，机器精度的空间分布恰好呈现竖向条纹，
   色标被拉伸至 10⁻¹⁴ 量级后显示为显著"不稳定性"（实际峰-峰变化 < 1.1×10⁻¹⁴）。

`plot_vorticity` 存在同样问题：均匀流场的涡量也为机器精度零，而旧版以 `v > 0`
作为 `TwoSlopeNorm` 启用判据（机器精度时 `v > 0` 为真），同样会放大噪声。

**修复方案：**

**`plot_velocity_magnitude`：**

新增 `vmin`/`vmax` 参数（默认 `None`），并内置智能归一化逻辑：

```
当 vmin 与 vmax 均为 None（默认）且峰-峰相对变化 < 1%（均匀流判据）时：
    vmin = 0.0
    vmax = 1.5 × mean(|u|)
```

这将色标范围固定为物理有意义的区间（如 `[0, 0.075]`），机器精度噪声不再放大。
当流场含 > 1% 相对变化（如顶盖驱动方腔、圆柱绕流等），智能归一化不激活，
matplotlib 自动色标照常使用。

调用者可通过显式传入 `vmin`、`vmax` 绕过智能归一化，例如放大子区域变化：

```python
plot_velocity_magnitude(snap, vmin=0.049, vmax=0.051)
```

**`plot_vorticity`：**

将启用 `TwoSlopeNorm` 的判据从 `v > 0` 改为 `v > 1e-10`，防止机器精度
（≤ 10⁻¹⁴）水平的涡量触发对称归一化后被放大为显著条纹。

**新增回归测试：**

| 测试 | 验证内容 |

| `test_explicit_vmin_vmax_override_auto_normalisation` | 显式 vmin/vmax 不引发异常 |
| `test_non_uniform_field_not_clamped` | 顶盖驱动方腔（> 1% 变化）不触发自动归一化 |

#### Bug Fix：`apply_boundary_conditions` BC 施加顺序导致速度入口角节点约束失效

**文件：** `core/src/lbm/boundary.cpp`（`apply_boundary_conditions`）

**问题描述：**

旧版本的 `apply_boundary_conditions` 按注册顺序依次施加所有 BC。当配置为
**西壁 = `ZouHe_Velocity`（速度入口）、南北两壁 = `FullyDeveloped`（自由出口）**时：
1. `ZouHe_Velocity`（West）先执行，计算并设置了 SW/NW 角节点的入口 f 值；
2. `FullyDeveloped`（South）后执行，对整个南壁（含角节点 `(0,0)`）执行零梯度拷贝：
   `f[a](0,0) = f[a](0,1)`（所有 9 个方向），销毁了 ZouHe 刚刚写入的角节点约束。
3. 最终 SW/NW 角节点的入口速度约束被自由出口拷贝覆盖，导致角节点速度明显偏离规定值，
   并在每个时间步持续将错误宏观量输入 BGK/MRT 碰撞器，造成**物理结果不正确**。

同样问题也影响 `velocity_inlet_pressure_outlet.toml` 配置（`ZouHe_Pressure` + `FreeOutlet`
同时使用时）。

**修复方案：**

将单一注册顺序循环替换为**三轮优先级排序**（高优先级最后施加，在角节点处覆盖低优先级值）：

| 轮次 | BC 类型 | 优先级 | 说明 |
|------|---------|--------|------|
| 第一轮 | `FullyDeveloped` / `FreeOutlet` | 最低 | 零梯度外推，为角节点提供背景值 |
| 第二轮 | `BounceBack` / `BounceBackFullWay` | 中等 | 固壁无滑移，覆盖第一轮在固壁面上的值 |
| 第三轮 | `ZouHe_Velocity` / `ZouHe_Pressure` / `Guo_Extrapolation` | 最高 | 最后施加，始终在角节点处生效 |

`apply_corner_bounce_back` 仍在三轮之后执行（行为不变）。

- `configs/velocity_inlet_channel.toml`（West=ZH_Vel + East=FD + South=BB + North=BB，无此问题，但受益于更清晰的语义）
- `configs/velocity_inlet_pressure_outlet.toml`（West=ZH_Vel + East=ZH_Prs + South/North=FreeOutlet，**已修复**）
- `configs/velocity_inlet_free_outlet.toml`（West=ZH_Vel + East/South/North=FD，**已修复**）

分析了 GPU-LBM 计算中 CPU↔GPU 数据传输的瓶颈：磁盘写入（NPZ 压缩，~20 ms/次）远大于 GPU 计算（~1 ms/步），造成 GPU 空转等待。新增异步双缓冲输出 API，将上一时间步的下载与当前时间步的 GPU 计算重叠：

  - `GpuSolver::download_rho_u(LatticeGrid&)` — 同步仅下载 rho/u（6.3 MB，比 `download()` 少 7×）

本版本修复了三处导致仿真发散和物理结果不正确的 Bug。所有修复均在 `core/src/lbm/` 中进行，
不影响 IBM/FSI 模块、Rust 绑定、输出格式及配置接口。

#### Bug 1（致命）：Zou-He 北壁已知/未知方向完全颠倒

**文件：** `core/src/lbm/boundary.cpp`（`apply_zou_he_velocity`）

流式迁移使用周期性取模，北壁（j=ny-1）流式迁移后：
- **已知**（来自内部 j=ny-2）：$f_2$(N)、$f_5$(NE)、$f_6$(NW)
- **幽灵**（来自 j=0 周期延拓）：$f_4$(S)、$f_7$(SW)、$f_8$(SE)

旧版本错误地使用南壁公式：以幽灵值 $f_4+f_7+f_8$ 计算 $\rho_w$，
并覆盖内部真实分布 $f_2, f_5, f_6$。随仿真推进，幽灵值持续偏离真实状态，
密度累积错误，引发发散。

修复后：密度公式使用已知方向 $f_2+f_5+f_6$，设置幽灵方向 $f_4, f_7, f_8$。
同时补全了南壁、西壁、东壁的 Zou-He 速度 BC 实现（旧版本仅有北壁）。

#### Bug 2（致命）：反弹 BC 通用循环破坏已知方向

**文件：** `core/src/lbm/boundary.cpp`（`apply_bounce_back`）

旧版本的 `bb_node` 函数对所有方向循环 `for a in 1..9: f[a] = f[OPP[a]]`。
由于序贯覆写（先写低索引，后读高索引时值已被修改），导致：
- South/North 壁：已知切向分量 `f[1]` 被错误修改为 `f[3]`
- East/West 壁：幽灵方向 `f[8]`（SE）从未被正确设置；`f[2]`、`f[6]` 被污染

修复后改为面专用精准赋值，每面只覆盖对应的三个幽灵方向，保留已知方向不变。

#### Bug 3（次要）：`compute_macroscopic()` 在 BC 前计算，边界节点 ρ/u 不正确

**文件：** `core/src/lbm/solver.cpp`（`Solver::step`）

`stream()` 末尾第一次调用 `compute_macroscopic()` 时，边界节点 f 中仍含幽灵值，
ρ/u 不正确。旧版本 BC 应用后未重新计算，导致下步碰撞在边界节点使用错误宏观量。

修复后在 BC 应用后增加第二次 `compute_macroscopic()` 调用，确保边界节点 ρ/u 正确。
